Motivation

This research is motivated by the pitfalls of ICM. During ICM, mutual predictability(MP) is calculated at each iteration, rescoring all labels based on the updated context; this computes the exact MP, but a single iteration takes n (number of claims) API calls, and over n iterations this reaches a worst-case of O(n^2). Context also grows with n, increasing the cost. Discussing different baseline techniques, [CITE] describes the difficulties in reproducing ICM and how running ICM on 4 H200s takes hours; this incurs a high compute cost, so we try to solve efficiency and reproducibility issues with a new method by exploiting MP without explicitly maximizing it, at a linear cost rather than quadratic.

Approach

[CITE] shows that ICM, simple bootstrap, and debate are all instances of coherence maximization. ICM’s MP conditions each label on all others, while a similar approach could condition autoregressively on predecessors only. This bidirectional term is what makes ICM expensive; [CITE] also describes Gibbs sampling, i.e. repeatedly resampling one label conditioned on the rest; this converges to a distribution concentrated on high-coherence labelings. Our method builds directly on this theory: we use an autoregressive pass to obtain a high-coherence labeling cheaply, followed by greedy refinement using an approximation of MP as the optimization objective, to recover what the autoregressive sampling lost.

Logical Consistency: Consistency is defined over groups of claims sharing a consistency_id, and we enforce it as a hard constraint rather than a penalty, So, both phases will only emit labellings which are possible under the particular consistency rule of a particular dataset, So decisions are made per group rather than per claim, Phase 1 labels a whole group at once, Phase 2 proposes moves between the elements of the consistency group. Our consistency fix is stricter than in ICM, or baseline methods from [CITE], as ICM treats consistency as a soft penalty, so inconsistent labellings remain reachable and are repaired by a ConsistencyFix routine. [CITE] enforce consistency as a hard constraint but apply it after bootstrap iterations. In our method there is nothing to repair, as the inconsistencies are never reached. All three methods end up with consistent labels, so consistency itself is not what separates them. The real question is which feasible labelling each one picks. For a group with more than one feasible option, something has to choose. ICM chooses by MP: its repair routine enumerates the consistent options and takes whichever maximizes the scoring function. [CITE] choose by confidence alone: the highest-scoring claim in the group wins and the remaining labels follow from it, with MP playing no role. We use both, in sequence. Phase 1 chooses by confidence, as they do. Phase 2 can then move a group to a different feasible labelling when that raises MP. Our constraint is the strictest of the three, since infeasible labellings are never produced at all; our selection rule starts from theirs and is then refined under ICM’s objective.

Alpaca (pairwise preference): A group has two claims about the same pair of responses: one saying the first response is more helpful and harmless, the other saying the second is. Preference is antisymmetric, so exactly one of them is True, which leaves only two allowed labellings, and choosing one claim as True determines the other. There is no score threshold here, because one of the two must win; we simply take whichever claim the model scores higher. Since every group resolves to a single choice between two options, claim-level and pair-level accuracy are the same number, and random guessing scores 50%.

GSM8K (solution verification): A group has four candidate solutions to one math question. Two rules apply: solutions that arrive at the same final numeric answer must get the same label, and no more than one answer value can be True. So an allowed labelling either marks every solution reaching one particular answer as True and the rest False, or marks all four False, the second case meaning none of the candidates got the question right.

TruthfulQA: A group is all the claims about one question, split into two sets by whether they are true or false. Claims in the same set always get the same label, and at most one set is labelled True. Our implementation reads this split using the gold labels, same as the leakage reported by [CITE] from [CITE] to make the methods comparable.

Phase 1

This is an ordered autoregressive labeling pass; we label the training set in a single pass from start to end, appending each labeled example to a growing context window. Each new label is sampled conditioned on all the labels assigned so far. Examples are ordered by model confidence described in [CITE] so that the labels the model is most certain about are labeled first, forming a strong context that can be used to label examples the model finds difficult. This mirrors the accept-reject dynamics of ICM. Following this, we calculate the total MP of the complete labeling that we have obtained.

Phase 2

Computing MP takes one model call per example, so a single exact evaluation would cost a full pass over the dataset. Testing every candidate move would mean a full pass per move, which is quadratic in complexity. We avoid this by proposing flips cheaply and then verifying using the exact MP calculation. So, first we start with proposing flips, changing a consistency group’s labels affects MP in two ways. It changes the scores of that group’s own claims, and it changes the scores of every other claim in the dataset, because the group’s labels sit in their context. We measure only the first effect: for each allowed labelling of a group, we ask how much log-probability the model assigns to those labels versus the ones currently in place, and we take the move if the answer is positive. All of these comparisons are made against a single snapshot of the labelling, taken at the start of the sweep. Because that context never changes mid-sweep, the scores can be computed once and reused for every move we consider, so the whole sweep costs one pass over the data. Second, verifying the sweep, freezing the context means every move is evaluated as if it were the only one, moves are proposed in parallel rather than in sequence, so none of them sees the effect of the others. Gibbs sampling, by contrast, updates one label at a time and each update sees the last. Once the sweep is done, we compute MP exactly, one more full pass. Phase 2 repeats, each sweep covering every example. After each sweep we recompute the exact MP and compare it to the previous value: if the improvement is below three percent, we stop and take the labelling from the last accepted sweep as our output. In practice this converges in a small number of sweeps, so the total cost stays linear in dataset size (n).

Results

These are the main results and comparisons directly against ICM, we use the many shot results figure 8 from [CITE] and compare it to our method, in alpaca they don’t mention accuracy after using gold labels which we evaluate at around 67%-68% just below our 69%, For TruthfulQA our number is 89.7% which is very close to the gold ceiling of 90.4%. The aforementioned tests and train were run on Llama 3.1 70B. For GSM 8K, we use Llama 3.1 8B to compare our results directly with ICM; results show our method reaches about 69%, which is similar to the gold ceiling.

We also ran experiments using categories of TruthfulQA instead of the whole set at once. Running tests after segmenting train and test labels on TruthfulQA by category gives an aggregate test accuracy of 88%. An interesting result was that when we used the complete train label set after regrouping all labels (after training separately for each category) and then tested on the whole test set as many-shot, we got a test accuracy of 89.4%, similar to the result on the whole set.

Other Experiments

We did other experiments like which labels to select for few shot prompting, based on confidence scorers after the labelling, balancing true and false labels in few shot prompts, we understood a few key details from here, that selecting whole questions rather than individual claims with most confidence would result in better test scores, as selecting most confident labels might just be making the model select a set which is skewed towards false labels, as models are most confident about false claims, we then test balancing the few shot claims true and false labels, which doesn’t perform at par to selecting the most confident questions, but when we use both the approaches together i.e taking the most confident and label balanced whole question we get great few shot performance ie 88.3% accuracy on 64 shot.

We also ran experiments where the model provides reasoning along with labels in few-shot demos for the test, but this doesn’t help the labeling at all and decreases overall test accuracy. Another experiment uses hints for questions the model thinks are difficult: self-hints from the same base model (Llama 3.1 70B), hints from a weaker post-trained model (Llama 3.1 8B Instruct), and hints from a frontier proprietary model. The frontier model improves the labels by a significant margin, whereas self-hints do the worst; using the weaker post-trained model does well on a small set of questions but fails by a large margin on a larger set.
